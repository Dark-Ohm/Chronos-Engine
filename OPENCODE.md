# OPENCODE — Рабочий журнал

Четвёртый исполнитель проекта Chronos-Engine. Этот файл пишет ТОЛЬКО
Архитектор: задания, брифы, поправки. Твои отчёты — ТОЛЬКО в
`opencode-report.md` (перезаписывай под каждое задание: номер задания,
diffstat, список пропущенного с причинами, вопросы).
Цикл: задание здесь -> работа -> отчёт в opencode-report.md -> поправка/добро здесь.

## ПРАВИЛА ИСПОЛНИТЕЛЯ (идентичны CLINE.md/HERMES.md, обязательны)

1. **Нет разрешения на инструмент — значит НЕТ.** Уперся в запрет — СТОП,
   одна строка в отчёт: какой инструмент нужен и для чего.
2. **Сборку и тесты запускает Архитектор.** Твоя зона: правка файлов строго
   по заданию + отчёт «готово к сборке». cmake/ctest/gdb не трогать.
3. **Скоуп задания — граница.** Выход за него — сначала строка в отчёте,
   потом (после добра) правка. Молчаливый выход за скоуп = откат.
4. Не коммитить. Коммитит Архитектор после приёмки.
5. **НЕ используй автоматические текстовые замены по паттерну (regex/sed
   поверх нескольких вхождений разом) для правок внутри C++-структур
   (member-init-lists, сигнатур функций, тел лямбд).** Каждое вхождение
   читай в полном контексте охватывающего блока (от сигнатуры функции/
   конструктора до закрывающей `}`) и правь вручную. Причина этого правила
   — см. секцию «Почему это задание у тебя» ниже, это не абстрактная
   осторожность.
6. **Метод порта:** «взять файл целиком из донора» ЗАПРЕЩЕНО (см. историю
   CLINE.md HOTFIX-C). В этом задании донор не при чём вообще — это чисто

## Почему это задание у тебя

Задание O-3 делал омп (третий исполнитель проекта) и провалил его три
раза подряд: первый раз — сломанная структурная скобка (пропущенный
`} else {`), второй раз — пропущенный `add_opt(common_arg(` у соседнего
CLI-флага, третий раз (это самое задание) — файл `src/llama-kv-cache-dsv4.cpp`
оказался структурно разрушен автозаменой: у одного конструктора пропал
параметр `llama_context * lctx` (использовался в теле, но исчез из
сигнатуры — не компилируется), member-initializer `kv_swa(...)` оказался
СНАРУЖИ любого конструктора (голый код между функциями), третий
конструктор получил ДВА одинаковых `ctx_base_mem(...)` инициализатора,
а свободная функция `dsv4_build_full_sinfo` (не конструктор, не класс)
получила member-init-синтаксис вместо простой строки `sinfo.resize(n_stream);`.
Отчёт при этом описывал результат как «7 аккуратных точечных замен» —
не соответствовало фактическому диффу ни в одной из этих точек. Омп
уволен с проекта. Файл я откатил сам (`git checkout --`) — сейчас в нём
7 исходных `static_cast`, чистая база, ничего наследовать не нужно.

Задание концептуально простое (замена cast + assert), но требует
АККУРАТНОСТИ при работе с C++ member-initializer-list синтаксисом,
особенно когда часть значений члена вычисляется через cast, а
конструктор принимает несколько параметров, некоторые из которых
используются в других частях init-list или в теле.

## ЗАДАНИЕ O-3 (переезд с omp) — DSv4: убрать неявный UB-инвариант в static_cast

`src/llama-kv-cache-dsv4.cpp` содержит 7 мест вида
`static_cast<llama_kv_cache *>(kv_raw->get_base())` (и `get_swa()`,
и `kv->get_base()/get_swa()` в другом классе того же файла), а
`get_base()`/`get_swa()` возвращают `llama_memory_i *` (может быть И
`llama_kv_cache`, И `llama_kv_cache_kvarn` — сиблинги, не связаны
наследованием). Сейчас это НЕ UB на практике: единственное место
конструирования `kv_raw` (llama-kv-cache-dsv4.cpp:975-977) хардкодит
kvarn=disabled, так что базовый класс там гарантированно `llama_kv_cache`.
Но это НИГДЕ явно не закреплено — молчаливо сломается (полновесный UB),
если кто-то в будущем передаст туда реальный kvarn. Задача: сделать
инвариант явным через assert, не менять логику.

### Метод (важно)

1. Найди все места: `grep -n 'static_cast<llama_kv_cache \*>' src/llama-kv-cache-dsv4.cpp`
   (сейчас должно быть 7).
2. Для КАЖДОГО вхождения — прочитай ВЕСЬ охватывающий блок целиком (если
   это внутри тела функции/лямбды — читай от `{` до `}` этой функции;
   если это внутри member-initializer-list конструктора — читай ВСЮ
   сигнатуру конструктора (все параметры) и ВЕСЬ init-list до тела `{`).
   Не полагайся на номера строк из старого задания — они устарели после
   отката, ищи заново по grep.
3. Замена:
   - **Если cast стоит в теле функции** (обычный statement, не
     member-init-list) — просто раздели на 2 строки:
     ```cpp
     auto * base = dynamic_cast<llama_kv_cache *>(kv_raw->get_base());
     GGML_ASSERT(base != nullptr && "DSv4 raw kv_raw is expected to never be kvarn-backed");
     // дальше используй `base` вместо повторного cast
     ```
   - **Если cast стоит внутри member-initializer-list** (например
     `kv_swa(static_cast<llama_kv_cache *>(kv->get_swa()))` как часть
     `ctor(...) : member1(...), kv_swa(static_cast<...>(...)), member3(...) {`)
     — ОБЯЗАТЕЛЬНО сохрани member-init-list синтаксис (это не тело функции,
     туда нельзя вставить два отдельных statement). Используй IIFE-лямбду:
     ```cpp
     kv_swa([&]() {
         llama_kv_cache * s = dynamic_cast<llama_kv_cache *>(kv->get_swa());
         GGML_ASSERT(s != nullptr && "DSv4 iswa SWA is expected to never be kvarn-backed");
         return s;
     }()),
     ```
     ВАЖНО: эта замена меняет ТОЛЬКО содержимое скобок одного члена
     `kv_swa(...)` — остальные члены init-list (`ctx_base_mem(...)`,
     `n_kv(...)`, `status(...)` и т.д.) и сигнатура конструктора (все
     параметры, включая `llama_context * lctx` если он есть) должны
     остаться БУКВАЛЬНО как были, кроме этого одного члена.
4. **Свободная функция `dsv4_build_full_sinfo`** (сигнатура
   `static llama_kv_cache::slot_info dsv4_build_full_sinfo(const llama_kv_cache * kv)`)
   — параметр уже `const llama_kv_cache *`, НЕ `llama_kv_cache_iswa *`.
   В её текущем (откаченном) виде проверь: есть ли там вообще
   `static_cast<llama_kv_cache *>`. Если нет (параметр уже нужного типа)
   — эту функцию НЕ трогай вообще, она не в scope задания.
5. После каждой правки — перечитай ИЗМЕНЁННЫЙ блок целиком ещё раз, как
   компилятор: сигнатура функции/конструктора не потеряла параметров,
   member-init-list не продублировал членов, фигурные и круглые скобки
   на месте.

### Границы

- Файл: src/llama-kv-cache-dsv4.cpp. Только замена static_cast на
  dynamic_cast+assert (в теле — 2 строки, в init-list — IIFE-лямбда).
  Ничего больше не переписывай, не трогай логику вокруг.
- Не трогай сам факт «kv_raw всегда disabled kvarn»
