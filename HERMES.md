Research и дизайн-док, БЕЗ КОДА. Правки в дереве: только новый файл

tiered offload принят (D-014), Phase 1 в реализации; Phase 2 — H2O
heavy-hitters в hot-tier — теперь нужен его детальный дизайн.

### Вопросы, на которые док обязан ответить
1. **Скоринг**: как считать attention mass на токен в llama.cpp-графе,
   где flash-attn НЕ материализует KQ-матрицу. Варианты из литературы
   (H2O, SnapKV, TOVA — у тебя уже есть источники) + что реально
   доступно у нас: отдельный лёгкий скоринг-проход? скоринг только на
   prefill? аппроксимация по нормам K? Каждому варианту — цена по
   памяти/скорости на ФАКТИЧЕСКОЙ архитектуре Qwythos.
2. **Гранулярность**: kvarn живёт группами по 128 токенов — H2O-отбор
   пер-токен или пер-группа? (пер-группа радикально проще с нашим
   форматом — честно взвесь потерю точности отбора).
3. **Бюджет**: сколько H2O-токенов/групп держать в VRAM при бюджете
   0.2-0.8GB (см. D-014), формула от n_ctx и битности.
4. **Обновление**: отбор один раз на prefill или скользящее обновление
   на decode; что происходит при seq_rm=FULL (D-011).
5. **Интерфейс с Phase 1**: какие поля/хуки Phase 1-кода понадобятся
   (координация: Phase 1 сейчас пишет Zed по дизайну O-10 — твой док
   должен требовать минимум изменений его слоя, перечисли требования
   явно списком «Phase 2 needs from Phase 1»).
6. Каждое утверждение из литературы — со ссылкой (правило H-10).
   Числа качества (retention/PPL) — только из источников, с указанием
   на чём мерили. Прикидки помечай явно.
