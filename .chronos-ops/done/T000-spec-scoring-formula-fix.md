## Почему первым (Волна 0, не параллельно с T003a)

`docs/design/h2o-heavy-hitters-PHASE2-SPEC.md` редактируют ДВА тикета:
этот (секция 1.3, формула scoring) и T003a (упоминания

конкурентных правок одного файла.

## Что сделать

`h2o-heavy-hitters-PHASE2-SPEC.md:47` (секция 1.3) содержит математически
бессмысленную формулу:

> Reuses the *same* KVarN flash-attention kernel path with a modified
> epilogue that writes `rowsum(softmax(QK^T))` to a side buffer instead
> of reducing into V.

`softmax(QK^T)` для фиксированного query суммируется в 1 по ключам ПО
ОПРЕДЕЛЕНИЮ softmax — `rowsum` тут тождественно даёт вектор единиц, ноль
информации о том, какой ключ важен.

Заменить на массу внимания, полученную каждым ключом, просуммированную
по всем query из observation-окна `W`:

```
score[key] = Σ_{query in W} softmax(QKᵀ)[query, key]
```

Проверить и поправить везде по файлу, где эта (неверная) семантика могла
протечь дальше — как минимум buffer-layout сразу под §1.3 (проверить,
не завязан ли размер/семантика буфера на rowsum-предположение).

## Верификация

- Формула в файле математически корректна: агрегация по query-измерению
