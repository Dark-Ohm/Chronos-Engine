# T013 — кламп/варн `--kv-hot-size` при включённом cold offload

**Роль:** `src/llama-kv-cache-kvarn.cpp` (ctor — там же, где кламп
`h2o_groups` из [[T003a]]), при необходимости `common/arg.cpp` (текст help).
**Приоритет:** P2. Свободен, ни от чего не зависит.
**Источник:** хвост №1 отчёта [[T003b-pre]] (2026-08-16). Тикет заведён
Архимагом, чтобы граница не осталась только в комментарии к коду.

## Проблема

T003b-pre вывел инвариант безопасности cold-копий:

```
копия группы g безопасна, пока   R > 1 + ubatch_groups
R = visible - tail + in_flight - 1,  in_flight = ubatch_groups
=>  гейт сводится к   visible > tail + 2    (члены ubatch сокращаются)
```

Для SWA-хвоста `tail = 2` это `hot >= 512` токенов. При `hot = 384` мы
ровно на границе (небезопасно в худшей выкладке), при `hot <= 256` копии
теряются **даже с per-ubatch дренажем**, который T003b-pre уже внедрил.

Сегодня ничто не мешает пользователю запустить `--kv-hot-size 256`
и молча получать испорченные cold-копии. Ровно тот класс тишины, который
мы только что поймали замером, а не чтением.

## Что сделать

1. В ctor `llama_kv_cache_kvarn`, где уже считаются `n_groups_per_stream`
   и `tail_groups`, проверить инвариант `visible > tail_groups + 2` —
   **только когда cold offload реально включён** (`cold_groups_per_stream
   > 0`), иначе флаг ни на что не влияет и предупреждать не о чем.
2. Поведение при нарушении — **решение Архитектора, не исполнителя**:
   кламп вверх до безопасного минимума с `LLAMA_LOG_WARN` (как сделан
   кламп `h2o_groups`) либо жёсткий отказ. По умолчанию бери кламп: он
   уже канон в этом файле, а отказ ломает существующие запуски.
   Формулировать варн числами: запрошено / безопасный минимум / из чего
   он получился (`tail_groups`), не «слишком мало».
3. Не выводить `tail = 2` константой: считать из `tail_groups`, чтобы
   non-SWA путь (`tail_groups + 1`) не разъехался.
4. Help `--kv-hot-size` в `common/arg.cpp:2288` — добавить, что при
   cold offload значения ниже безопасного минимума клампятся.

## Чего НЕ делать

- Не расширять кольцо и не менять layout/версию state — это смена
  формата, отдельный разговор (см. хвост №1 отчёта T003b-pre).
- Не трогать сам дренаж: он уже per-ubatch и верифицирован.
- Не трогать поля H2O ([[T003a]]) и логику пина ([[T003c]]).

## Верификация

- Живой запуск с `--kv-hot-size 256` и включённым cold offload: варн
  виден, эффективное окно — безопасное, сервер поднимается.
- Живой запуск с `--kv-hot-size 512`: ни варна, ни изменения окна.
- Без `--kv-hot-size`: ноль изменений в поведении и в логе.
- Регресс-проверка хэшей копий по методике [[T003b-pre]] на клампнутом
  запуске: 128/128 различны. Артефакты — в отчёт, числа подстановкой.
