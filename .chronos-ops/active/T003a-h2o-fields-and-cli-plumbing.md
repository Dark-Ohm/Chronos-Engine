## Что сделать (SPEC §5, строки 2/3/6 таблицы хуков)

### 1. Поля в `llama_kv_cache_kvarn` (`src/llama-kv-cache-kvarn.h`)

- **`h2o_group_flags` — размер `max_groups × n_layers`.** Пин-биты
  ПО СЛОЯМ. Глобальный вектор на `max_groups` — ошибка: слои выбирают
  разные группы (T003d, блокер 2), и один общий bitmask физически не
  может их представить. Организацию (упакованные биты или bool-массив)
  выбрать и обосновать, сверив с уже существующими per-layer структурами
  этого класса (`layer.k_records` и соседи) — не выдумывать новую.
- **`h2o_group_scores` — `float`, форма `[n_kv_heads][max_groups][n_layers]`.**
  Накапливается по ходу prefill (T003c), читается selection-логикой; в
  этом срезе только аллоцируется и зануляется. Для Qwythos это
  4 × 2048 × 8 × 4 Б = 256 КБ.
- **`h2o_key_scores` НЕ ЗАВОДИТЬ.** Этого буфера в дизайне больше нет:
  он существовал только для отдельного scoring-пасса, который отклонён
  (SPEC §1.2). Если встретишь его в старом тексте — это мёртвое имя.
- `h2o_groups` — количество пинов (0 = выключено), плюс производный
  `const bool h2o_enabled;` по образцу `cold_offload`
  (`llama-kv-cache-kvarn.h` — номера строк сверить по факту, могли
  сместиться).
- **Потолок пина.** Число пинов ограничено долей `n_groups_per_stream`
  (`llama-kv-cache-kvarn.h:224`). В этом срезе — только сохранить
  значение и валидировать его при конструировании (клампить с
  предупреждением, а не молча). Сам механизм удержания — T003c.

### 2. CLI `--kv-h2o-groups N`

Единицы — **группы** (группа = 128 токенов), без округления к 128.
Существующий `--kv-hot-size` (`common/arg.cpp:2288`) измеряется в
**токенах** с округлением к 128 — это осознанно РАЗНЫЕ единицы у разных
флагов, и help-текст `--kv-h2o-groups` обязан это назвать прямо, чтобы
следующий читатель не решил, что флаги «зеркальные».

Проводка — **по образцу `kv_hot_size`**: он живёт РЯДОМ с kvarn-параметрами,
а не внутри `llama_kvarn_params`. Слота `cparams.kvarn.h2o_groups` не
существует, и заводить его внутри структуры kvarn НЕ НАДО — повторить
раскладку `kv_hot_size` один в один: `common/arg.cpp` → `common/common.h/.cpp`
→ `include/llama.h` → `src/llama-cparams.h` → `src/llama-context.cpp` →
через `src/llama-model.cpp` до ctor `llama_kv_cache_kvarn`.

Номера строк-ориентиров проверять по факту дерева.

### 3. Явно НЕ входит

Накопление скоров в attention-пути, любой выбор top-K, пин против
перезаписи в кольце, любые правки `store()`/`view()`/live-set,
prefetch-слоты, `ggml-cuda/`. Если `h2o_group_flags` в этом срезе некому
писать — так и задумано: поле всегда пусто.

## Критерий «готово»

- Компилируется.
- Без флага (или 0) — поведение идентично текущему, `h2o_enabled=false`,
  поля не аллоцируются. Это критерий приёмки, не пожелание.
- С флагом — сервер поднимается; функционально ничего не меняется.
- Значение выше потолка (доля `n_groups_per_stream`) — клампится с
  внятным предупреждением, а не принимается молча.

## Отчёт
