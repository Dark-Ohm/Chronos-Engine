## Что сделать (SPEC §5, пункты 1-3 и 6 из списка хуков — без урезаний)

### 1. Поля в `llama_kv_cache_kvarn` (`src/llama-kv-cache-kvarn.h`)

- `h2o_group_flags` — bitmask/bool-массив размер = max_groups, схему
  выбрать и обосновать (не выдумывать новую организацию per-layer
  данных — сверить с уже существующей в этом классе).
- `h2o_scores` — **`float *`, размер строго `max_groups × n_layers`**
  (SPEC, `h2o-heavy-hitters-PHASE2-SPEC.md:188`, дословно из таблицы
  «Phase 2 needs from Phase 1» — per-group средний скор, ОДИН массив на
  все слои с этим множителем, не отдельный массив на слой и не общий
  без слойного измерения). Записывается scoring-пассом (T003c), читается
  selection-логикой — в этом срезе только аллоцируется/зануляется.
- `h2o_groups` — количество групп, аналог `kv_hot_size` у Z-2 (0 =
  выключено).
- Паттерн Z-2: `const uint32_t h2o_groups;` в членах, производный
  `const bool h2o_enabled;` — по образцу `cold_offload`
  (`llama-kv-cache-kvarn.h:229`, `.cpp:519` — сверить номера, могли
  сместиться со времени исходной раздачи).

### 2. CLI `--kv-h2o-groups N`

**Не путать единицы с `--kv-hot-size`.** Проверено сегодня
(`common/arg.cpp:2288-2303`): `--kv-hot-size` измеряется в **токенах**
(help-текст: «size of the KVarN hot window in tokens», округление до
кратности 128 внутри парсера) — это НЕ количество групп, вопреки
формулировкам в SPEC (см. «Побочная находка» ниже). Новый
`--kv-h2o-groups` по своему имени — сознательно другая единица
(количество групп напрямую, без округления к 128, т.к. группа сама по
себе = 128 токенов) — это ДОПУСТИМО как разный дизайн для разных
флагов, но обязано быть явно прокомментировано в help-тексте
`--kv-h2o-groups`, чтобы не создавать у следующего читателя ложное
ощущение единообразия с `--kv-hot-size` через «зеркалирование».
Проводка (не единицы, а сам механизм): `common/arg.cpp` (парсинг),
`common/common.h/.cpp`, `include/llama.h`, `src/llama-cparams.h`,
`src/llama-context.cpp`, через `llama-model.cpp` до ctor
`llama_kv_cache_kvarn` — по образцу структуры кода `kv_hot_size`, не по
образцу его единиц измерения. Номера строк-ориентиров проверить по
факту дерева, не доверять номерам из исходной раздачи месячной давности.

## Побочная находка (закрыть тут же, но НЕ механической заменой строки)

`docs/design/h2o-heavy-hitters-PHASE2-SPEC.md` использует
`--kv-hot-groups` по всему тексту (строки 97/123/141/191/239) и меряет
Phase 1 hot-window в ГРУППАХ (пример: «default: 4 = 512 tokens»).
Реально реализованный флаг — `--kv-hot-size`, и он принимает **токены
напрямую** (512, не 4) — см. п.2 выше. Это значит: правка спеки — не
`s/--kv-hot-groups/--kv-hot-size/`, а пересчёт формул и примеров с
групп на токены по всему файлу (`hot_groups = N` → `hot_size (tokens) = N × 128`
и наоборот, где нужно). Синхронизировать ПЕРЕД тем как писать
`--kv-h2o-groups` по образцу — иначе зеркалируется не просто опечатка
имени, а рассинхронизированные единицы измерения.

## Критерий «готово»

- Компилируется.
- Без флага `--kv-h2o-groups` (или 0) — поведение идентично текущему,
  `h2o_enabled=false`, поля не аллоцируются/не используются. Это
  критерий приёмки, не пожелание.
- С флагом — сервер просто ПОДНИМАЕТСЯ (поле есть, ничего с ним активно
  не делается) — не обязан ничего давать функционально, чистая
  подготовка почвы.
