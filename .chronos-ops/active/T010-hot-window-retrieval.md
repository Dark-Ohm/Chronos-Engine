# T010 — `--kv-hot-size` ломает retrieval даже внутри окна

**Роль:** `src/llama-kv-cache-kvarn.*`, возможно `src/llama-graph.*` /
`src/llama-kvarn.*` (read-путь, SWA/`mat_idxs`).
**Приоритет:** P1 — баг корректности Phase 1. Без живого закрытия
бессмысленны T003b-pre / T003b / T003c (H2O поверх сломанного окна).
**Источник:** выписано из корневого `ZED.md` (задание Z-4, 2026-07-19).
Находка G-4 (`.chronos-ops/dump/grok-report-G4.md` §3a). 27+ дней без
движения — статус в брифe НЕ считать подтверждённым; воспроизвести заново.
**Зависимости:** нет. Блокирует T003b-pre, T003b, T003c.

## Симптом

`--kv-hot-size` на не-SWA модели включает фейковый `SWA_STANDARD`
(`llama_kvarn_apply_hot_window`). Сервер не падает, но отвечает мусором
даже когда весь промпт помещается в окно. Это не «деградация за
пределами окна по дизайну Phase 1» — игла внутри окна пропадает.

## Воспроизведение (G-4 §3a; сверить модель/бинарник на текущем HEAD)

```
# Без флага — игла находится:
llama-server -m $MODEL -ngl -1 -fa on -c 8192 -ub 256 -fit off -np 1 \
  --cache-type-k kvarn4 --cache-type-v kvarn4 --port 8099
# промпт 1763 токена, игла "BLUE-ORBIT-7749" в начале -> ответ содержит иглу

# С --kv-hot-size 4096 (>> 1763, весь промпт обязан быть hot) — ломается:
# тот же промпт -> мусор ("Dolor"), иглы нет
```

На длинных промптах (~50K): игла в конце (должна быть в hot) не
находится с флагом и находится без; изредка HTTP 500 (peg-native) —
вероятный симптом того же корня, не отдельная причина.

## Рабочая гипотеза (проверить первой, не принимать на веру)

`view()` в SWA-режиме читает `indices = mat_idxs` — абсолютные позиции
(`cells.pos_get`). `store()` / `ggml_kvarn_store` получает другой
`indices` (slot/cell кольца из `self_k_idxs`). Если `GGML_OP_KVARN_VIEW`
ждёт индекс кольца, а получает растущую позицию — краша не будет,
чтение уйдёт в чужой слот. Ровно симптом «не падает, мусор».

Если не она — дальше: off-by-one по cells, wraparound `cell` > размера
ring, рассинхрон store/view пока SWA-кольцо едет.
