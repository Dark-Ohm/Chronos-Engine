# OPENCODE Report

## O-7 — квантование-как-продукт: разведка + известные пробелы

### Формат-совместимость TurboQuant со стоковым llama.cpp/Ollama

**ОТВЕТ: НЕ СОВМЕСТИМО.** TurboQuant использует кастомные GGML_TYPE и ftype ID:

| Тип | GGML_TYPE ID | ftype | Стандартный? |
|---|---|---|---|
| TQ1_0 | 34 | 36 | НЕТ — upstream llama.cpp не знает эти ID |
| TQ2_0 | 35 | 37 | НЕТ |
| TQ3_1S | 206/207 (наш)/47/48 (донор) | 43/44 (только донор) | НЕТ — в нашем дереве даже нет LLAMA_FTYPE |
| Q4_0 | 2 | 2 | ДА |

GGUF-контейнер стандартный, но типы внутри — кастомные. `llama-quantize` CLI поддерживает только TQ1_0/TQ2_0. TQ3_1S/TQ4_1S не имеют ftype в `llama.h`, не входят в `llama-quantize`, и у них нет quantize-диспетчера в нашем `ggml.c` (в доноре есть, у нас — нет). **Стоковый llama.cpp/Ollama упадёт при попытке загрузить TQ-файл.**

**Дополнительно: CUDA-поддержка TQ — НОЛЬ.** Ни одного упоминания TQ во всех файлах `ggml/src/ggml-cuda/`. Даже в нашем форке TQ-модель на GPU будет работать только через CPU-offload (экстремально медленно).

### Количественное сравнение

**НЕ ВЫПОЛНЕНО.** На машине нет .gguf моделей (только Ollama-манифесты). Для сравнения нужен хотя бы один FP16 .gguf для квантования в Q4_K_M и TQ2_0. Рекомендация: скачать модель (например Qwythos-9B-v3-1M-MTP в FP16, ~18GB) или использовать существующую, если доступна через `huggingface-cli`.

Известные битрейты из `llama-quantize --help`:
- TQ1_0: 1.69 bpw (ternarization)
- TQ2_0: 2.06 bpw (ternarization)
- Q4_0: ~4.34 bpw @ Llama-3-8B

TurboQuant даёт ~2.5x меньший размер vs Q4_0, но качество и скорость без тестов неизвестны.

### Итоговая рекомендация

**TurboQuant/KVarN как внешний продукт НЕ ГОТОВ.** Три блокера, в порядке приоритета:

1. **CUDA-кернелы для TQ-типов** (без них модель не работает на GPU — а пользователи без GPU ничтожны)
2. **Upstream PR в llama.cpp** (без стоковой совместимости «скачай .gguf и запусти» не работает — продукт требует捆绑 форка)
3. **TQ3_1S/TQ4_1S пайплайн** (quantize + ftype + model-loader) — WHT-rotated типы обещают лучшее качество, но их даже заквантовать нельзя

Пока эти три блокера не закрыты, продукт «квантованные модели» не имеет смысла обсуждать. **KVarN** (KV cache quant, не веса) технически ближе к продакшену — он живёт только в нашем форк-сервере, не требует стоковой совместимости, и O-6/O-8 почти закрыли последний блокер seq_rm.
