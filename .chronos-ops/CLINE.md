# CLINE — Рабочий журнал

Этот файл пишет ТОЛЬКО Архитектор. Файл держит ТОЛЬКО текущее задание —
история заданий и приёмок в `git log -- .chronos-ops/CLINE.md`. Отчёты —
в `cline-report.md` рядом (перезаписывай под каждое задание).

## ПРАВИЛА ИСПОЛНИТЕЛЯ (обязательны)

1. **Нет разрешения на инструмент — значит НЕТ.** Уперся — СТОП, строка в отчёт.
2. **Сборку и тесты запускает Архитектор.** cmake/ctest/gdb не трогать.
3. **Скоуп задания — граница.** Молчаливый выход за скоуп = откат.
4. Не коммитить. Коммитит Архитектор после приёмки.
5. Никаких regex/sed-замен по нескольким вхождениям разом в C++-коде.
6. «Взять файл целиком из донора» ЗАПРЕЩЕНО — только адресные правки.

## ЗАДАНИЕ C-3 — test-backend-ops: покрытие turbo/kvarn/WHT операций

### Контекст
G-3 (формальная валидация, принята) нашла гэп: `test-backend-ops`
проходит 13994/13994, но **ноль** кейсов с именами turbo/kvarn/TURBO_WHT/
KVARN_* в покрытии (`rg -ic "turbo|kvarn|WHT|TURBO"` по логу → 0). Значит
весь путь G-1 (SIGSEGV-фикс), G-2 (inv-WHT + CPU turbo2/3 quantize),
Z-2/Z-3 (SWA KVarN ring) — НЕ застрахован тестовым сьютом. Suite зелёный
не потому, что эти опы проверены, а потому что их там просто нет.

### Что сделать
1. Найди, как `test-backend-ops` регистрирует тест-кейсы для операций —
   `tests/test-backend-ops.cpp` (структура `test_case`, функция типа
   `make_test_cases()` или аналог — сверь по факту точное имя).
2. Найди существующие тест-кейсы для похожих custom-опов (например,
   `GGML_OP_FLASH_ATTN_EXT` или любой другой уже покрытый кастомный оп) —
   это твой шаблон по стилю (как задаются размеры тензоров, допуски
   численного сравнения и т.д.).
3. Добавь тест-кейсы (адресно, не переписывай файл):
   - `GGML_OP_KVARN_VIEW` (или как называется оп в нашем дереве — найди
     точное имя через `grep -rn "GGML_OP_KVARN" ggml/`) — базовый
     forward-тест на паре размеров тензоров, соответствующих KVAR_N_GROUP=128.
   - `ggml_turbo_wht` (инверсия WHT после attention, G-2) — тест forward
     на F32-тензоре, кратном 128 по последней размерности (см. гейт в
     `src/llama-graph.cpp` — `cur->ne[0] % 128 == 0`).
   - Quantize/dequantize round-trip для turbo2/3/4_0 (используй
     существующий паттерн quantize-тестов в файле, если такой есть —
     не выдумывай новый механизм).
4. Если какой-то из этих опов физически не тестируется на CPU (только
   CUDA-путь) — явно напиши это в отчёте, не пытайся обойти хаком.

### Границы
- Файл: только `tests/test-backend-ops.cpp`.
- Не трогай реализацию самих опов (`ggml/src/...`) — только добавляешь
  тестовые кейсы для уже существующего кода.
- Если для добавления кейса не хватает публичного API (например, нет
  способа собрать граф с нужным опом через существующие ggml-функции) —
  СТОП, строка в отчёт с точным описанием, чего не хватает.

### Отчёт

компилируется).
