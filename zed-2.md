# ZED — задание №2.1: живой прогон через Zed editor's AI agent (отдельный трек, не Alloy)

_Дата: 2026-07-18. Отчёт — `zed-2-report.md` в корне ЭТОГО репо
(Chronos-Engine, не ChronOS). **Это НЕ продолжение твоего задания №1
в ChronOS (Alloy → трей-виджет)** — отдельный, независимый трек в
ДРУГОМ проекте. Не путай файлы/репо, не трогай ChronOS._

## Контекст

Сегодня в Chronos-Engine (форк llama.cpp с TurboQuant/KVarN) закрыт
последний известный блокер kvarn (`seq_rm` partial-removal краш —
задания O-6+O-8, коммит `367ca3bb8`). Живой прогон подтверждён: 5
запросов подряд с частичным cache-reuse, ни одного краша, плюс через
`chronos-host` (Chronos-IDE, ADK-Rust агент) — реальный tool-calling
раунд (codegraph_search) отработал корректно через наш
OpenAI-compatible эндпоинт.

Хочется ВТОРОЙ независимой валидации — насколько наш сервер (с
активным kvarn) совместим с реальным, популярным клиентом: **Zed
editor's built-in AI agent** (не Zed-редактор как IDE вообще, а именно
его агентская панель с поддержкой custom OpenAI-compatible провайдеров).
Это другой клиент с другим паттерном запросов (может слать иначе
устроенные multi-turn истории, другой tool-calling протокол, другие
объёмы контекста) — хороший стресс-тест для только что починенного
gating.

## Задача

1. **Подними сервер** (если ещё не поднят — проверь
   `pgrep -a llama-server`, скорее всего уже висит с прошлого прогона
   на порту 8099, не поднимай второй экземпляр если да):
   ```
   cd models/main && PORT=<любой свободный> ./run-server.sh qwythos-v3 -c 65536 -fit off
   ```
   Проверь порт: `curl http://127.0.0.1:<порт>/v1/models`.
2. **Настрой Zed editor** (уже установлен, `zed-preview.app`) — Settings
   → AI → добавить custom OpenAI-compatible provider с base URL
   `http://127.0.0.1:<порт>/v1`, модель — что вернёт `/v1/models`
   (путь к .gguf), API-ключ — любой, сервер не проверяет.
3. **Прогони реальную задачу** через агентскую панель Zed на этом же
   репозитории (Chronos-Engine) или на Chronos-IDE — что-то, что
   реально требует tool-calling (поиск по коду, чтение файла,
   многораундовый диалог с уточнениями) — НЕ просто одна короткая
   реплика. Цель — нагрузить контекст достаточно, чтобы задействовать
   partial cache-reuse (именно тот путь, который сегодня чинили).
4. **Наблюдай за сервером параллельно**: держи открытым лог
   (`RUST_LOG`/stdout сервера) и `pgrep -a llama-server` — если
   процесс упадёт или в логе появится `GGML_ABORT`/`GGML_ASSERT` —
   это самое ценное, что можно найти, зафиксируй ПОЛНЫЙ текст ошибки
   и что именно делал Zed-агент в этот момент (какой запрос/раунд).
5. **Если Zed-агент не умеет tool-calling через наш эндпоинт вообще**
   (несовместимый формат function-calling, например) — тоже ценный
   результат, опиши точно что сломалось (формат ответа сервера,
   ошибка в UI Zed, что угодно наблюдаемое).

## Явно НЕ требуется

- Не нужно чинить код Chronos-Engine самому, даже если найдёшь баг —
  это разведка/стресс-тест, не фикс-задание. Баг → в отчёт с
  максимальной точностью (лог, репро-шаги), фикс — отдельным заданием
  после разбора Архитектором.
- Не трогай `OPENCODE.md`/`CLINE.md`/HANDOFF.md — это твой отдельный
  файл-отчёт.
